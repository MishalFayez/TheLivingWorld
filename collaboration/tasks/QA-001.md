## Initial findings to investigate, not assumptions to patch blindly
1. smoke_runner disables Save.enabled only AFTER instantiating the main scene. main/Game startup may already have loaded real progress. Its Vanguard==1 assertion may therefore depend on the user's save. Reproduce on an isolated test path with pre-existing progress; determine real class switching correctness. Approved test correction: explicitly isolate deterministic fixtures before startup, preserve meaningful class-independence assertions, verify existing progress rather than weakening expectations.
2. save_system.gd save_game removes the old file before rename and ignores errors, returning true even on replacement failure; save_settings writes directly into the same file. Protect existing character data on failed writes and settings changes. Reproduce failure with isolated fixture paths. No deletion or overwrite of the user's real saves. Use normal error handling, validate existing data sufficiently to prevent destructive overwrite, preserve format/semantics. Report any migration/design question.
3. Game.switch_class currently assigns active_class even for an invalid class ID. Inspect callers and guard invalid input if it can leave inconsistent state; maintain normal class-switch behavior.
4. Independent ChatGPT code review: PlayerBrain.ACTIONS processes light before blade_modifier (and guard). A same-physics-frame Shift+A/D+LMB press can therefore read yesterday's modifier state in ReaverSwordmaster.read_direction(); same-frame modifier release can likewise retain lateral intent. Existing resolution tests set Hero.held directly and miss this real Input path. Reproduce using Input.action_press/release through an active PlayerBrain, then fix input ordering/snapshot only to implement the already approved chord. Cover both modifier press and release in the same frame as an attack. Also inspect same-frame Vanguard Guarded Strike without changing counter priority.
5. Debug isolation: main.return_to_menu resets progression and debug_tainted but not Game.invincible, permadeath, mage_core, reaver_core or auto_open_drafts. DebugPanel._set_core does not taint; Permadeath toggle may not taint either (inspect Game.set_flag). Reproduce whether experimental cores / invincibility / death-rule changes can leak into the next clean savable session. Approved technical correction: gameplay-affecting debug changes must taint and must be discarded on leaving the debug session; normal gameplay must restart with the existing defaults. Preserve ordinary user settings. Add regression tests for the actual leak.
6. PauseMenu.open increments Game.ui_block unconditionally, unlike GameMenu.open_tab. Repeated open calls may leave gameplay blocked after resume. Reproduce and make opening idempotent if confirmed; test pause/menu balance. Do not redesign UI.
